# Estimator Doctrine

Brain files are tools, not a bible. **Job evidence wins.**

**Canonical process:** `AI_HANDOFF/WORKFLOW.md` and `GROK_INSTRUCTIONS.md` (v4.0).

## Principles

| Rule | Meaning |
|------|---------|
| Job = **WHAT** | Schedules, plans, details, sequences, specs, matrices |
| GEMS / Template / Learn = **HOW** | Verbs, ownership, phrasing |
| Never invent | No Brain lines without evidence |
| Buildings do not merge | One building → one proposal |
| Takeoff before package | Real tags/qty before Primary 3 |
| Human issues | Tool drafts only |

## Production flow (summary)

1. Drop docs  
2. Register every page (text + vision)  
3. **Takeoff schedules per building** (vision if image)  
4. Path decisions (FE; VAV/FPB DDC-to-factory default; RTU from matrix+diagram)  
5. Write AME SOW  
6. Primary 3 only: Proposal + CloseOut + Evidence  
7. Human gate  

## GEMS

- Use GEMS rules whenever writing scope lines (even if control drawings exist).  
- GEMS works best when a **sequence of operation** is available.  
- Client proposal = clean equipment blocks; no GEMS QC dump.  

## Quantities

- Schedule (and confirmed bulletin counts) **primary**.  
- Conflicts → `*C#` on proposal; do not silently average or pick high.  
- **Do not leave TBD** when the schedule has numbers — read the schedule.  

## Image-only drawings / schedule tables

- Mark vision required → **vision takeoff before final counts**.  
- Full page register = coverage; schedule vision = takeoff.  

## Front end

- **New:** “Front End Web Enabled BMS System” (fat lines as specified).  
- **Existing:** “Seamlessly Tie in to the Existing … BMS”.  

## Terminal units (AME default ~99%)

`Furnish DDC Controller to the Factory for Installation` for VAV/FPB/FPT  
— not OEM factory-controls path unless schedule explicitly requires it.
