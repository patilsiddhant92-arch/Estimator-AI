## Findings, ranked

1. **Must fix before merge (contract gap in the base, not HarkPro's fault): `with_plant`.** The prompt
   (`src/bms/prompts/takeoff_job.md:17`) tells the AI to give `with_plant`; `Unit` on takeoff/s1
   (`src/bms/model.py:283-302`) has no such field and the schema sets `additionalProperties: false`. Reviewer
   check: an answer with `with_plant` on each unit gives `$.units[0]: unexpected with_plant` and is refused. Every
   answer that obeys the prompt is refused, up to `max_attempts`, and the run stops at "takeoff". Same root:
   `COUNTED_STATUSES = ("new", "relocate")` (`model.py:68`) where the amended Task 1.1 and the prompt's own Units
   section say relocate units do not count; `DemolitionLine`, `DEMOLITION_OF` and `Job.demolition` are absent.
   Fix: land the amended Task 1.1 on takeoff/s1 (or on top of T-006) before merge. HarkPro reported this (report
   section 5, question 1), and the spec hunk says so.
2. **Should fix before Stage 2 binds: the schedule floor can be met by citing the schedule's own row.**
   `_cites_beyond` (`src/bms/takeoff.py:171-181`) treats a ref as "beyond the schedule" unless its source text
   starts with `"<sheet> <title>,"`. The real dossier gives each schedule row its own source,
   `"<title> row <tag>, <where>"` (`src/estimator/writing/dossier.py:717`), and schedule notes
   `"<title> notes, ..."` (`:720`, `:723`); with no sheet the schedule source has no `"- "` prefix
   (`dossier.py:695` vs `takeoff.py:160`). So a ref to the unit's own row passes. Also, any non-schedule ref
   passes, even one that does not name the unit: `test_the_schedule_is_the_floor` (`tests/bms/test_takeoff.py:310`)
   accepts AHU-5 set aside by a keynote about AHU-6 and EF-6. Stage 1 counts nothing, so not blocking. Suggest:
   match the schedule by (document, page) and by the row/notes prefixes, and require the explaining quote to name
   the tag or one of its labels; let a row marked EXISTING (`row.existing`) explain itself.
3. **Risk, by design (lead to rule):** the takeoff step is on the critical path. A refused or missing answer
   (`run.py:513-517`) or a prompt over 600,000 characters (`takeoff.py:125`, caught as a stop at `run.py:478`)
   stops a run that worked before, although Stage 1 reads nothing from the register. This follows the plan.
   Finding 1 makes it likely on the first live run.
4. **Deviation, accepted:** the prompt uses curly quotes around its examples (8 lines). Words are the plan's;
   straight-quoted capitalised phrases would be read as rule citations by `playbook_lint.prompt_rule_names`. A test
   pins it (`test_takeoff.py:392-404`).
5. **Deviation, accepted:** no `tag_list` expansion. `tag_list` compresses, it cannot expand (the plan was wrong);
   the reading already gives one row per tag.
6. **Deviation, accepted:** the floor needs a reason and a non-schedule ref (stricter than plan test 5; it matches
   the binding decision "only with a cited passage"). `save` returns a bool and skips an identical file (needed by
   `test_correct_018f`); run prints "Wrote" only on write.
7. **Minor:** a ref to a ledger source that is not in `ai.evidence_index` is refused with "the ledger does not
   know" (`takeoff.py:145`); the words are wrong for that case. `by_tag` (`takeoff.py:215`) keys by tag only, so
   two families with one tag keep the last row. No check that `unit.sheets` names listed sheets or that a `future`
   unit has a future item (not in the plan).
