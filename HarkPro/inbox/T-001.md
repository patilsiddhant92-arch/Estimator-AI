# T-001: coverage gate (lead, 2026-10-11)

Base: `origin/rebuild` (ce07960 or later; if `rebuild` is not yet at ce07960 on GitHub, use `origin/rebuild` as it is
and say so). Branch: `hark/T-001`. Report: `HarkPro/outbox/T-001-report.md` on the same branch.

## The problem

A fact can be read from the job's documents into the ledger and then be printed nowhere: no scope line, no
clarification, no question, no exception cites it. The estimator does not see that it was lost. (Review items HP 35
to 40, 42, 58.) `bms/plan.py` `lost()` covers only families and tags in planning; nothing checks the written job.

## What to build

1. A new module `src/bms/coverage.py` with one pure function:
   `coverage(job: Job, ledger: Ledger, dossier=None) -> list[Finding]`
   - For each ledger fact of a kind that calls for scope (equipment families and their tags, control points, sequence
     sections, spec requirements that name controls work: you choose the list and say why in the report), find whether
     the written job cites it: a device ref, a family, a clarification, an exception, a question, or the front end.
   - Each fact that nothing cites gives one Finding: rule name `coverage`, severity `check`, the fact in plain words,
     where it is (sheet / spec section / page), and the fix ("Add a line, a clarification, an exception or a question
     that cites it, or mark it as not scope").
   - Never add a line or text to the job. The gate only reports (no fallback lines, no standard lines).
2. Tests in `tests/bms/test_coverage.py` with invented fixtures only (use `tests/bms/fixtures/` as a pattern; do not
   change the shared fixtures or `tests/bms/test_contracts.py`).
3. Do not edit `src/bms/model.py`, `playbook.py`, `run.py`, `__main__.py`, `playbook/` or `docs/superpowers/specs/`. The
   lead wires the gate into the run and the review page. In the report, say where you would call it (stage and
   function) and how the review page should show it.

## Limits

  count prints; every other count is a '*' note with both numbers).
- No job data in git. No real job names, tags, sheet numbers or text in code, tests or the report.
- Full suite: no failure outside your 12 baseline tests.
